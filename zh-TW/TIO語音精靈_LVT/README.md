# TIO語音精靈

用 Google 的 **Gemini 3.5 Transcribe / Live API** 做五件事：會議即時字幕、
錄音／錄影檔轉繁體逐字稿、即時雙語字幕、逐字稿轉雙語對照文件、即時語音翻譯（口譯模式），
外加一支純本機的逐字稿重新排版。全部已在本機實測跑通。

一般使用者從雙擊 `4_開始使用.bat` 開始，會看到中文選單，不需要打任何指令。
以下的 `python scripts/xxx.py` 是給要直接用命令列、或要接進自己流程的人看的。

> 🔴 動手前先讀 [`references/gemini-speech-guide.md`](references/gemini-speech-guide.md)。
> 裡面有踩過的坑，特別是**繁體字陷阱**與**免費層不能錄真實會議**這兩條。

## 安裝與解除安裝

**一般使用者**：雙擊 `3_安裝.bat`。沒有 Python 的電腦會先跳出中文對話框說明並徵求同意，自動裝好 Python 後**直接接續**（不需要關掉視窗重跑）。
接著跳出**安裝精靈視窗**：先列出「會在你電腦上做哪些事」（通常四件；有舊版殘留檔或「來自網路」標記時會多一兩件），
按下「我同意，開始安裝」才動手，過程有進度條與逐步紀錄，失敗會把真正的錯誤訊息貼出來。
裝完桌面會有「TIO語音精靈」捷徑，點兩下就能用。

> 沒有 tkinter 的 Python（極少見）會自動退回文字版 `scripts/setup.py`。
> ⚠ **不是完全一樣**：文字版不會建立桌面捷徑、不會清舊版殘留檔，也沒有 SSL/truststore 自動重試。

**不想用了**：雙擊 `7_解除安裝.bat`，會跳出解除安裝精靈，逐項勾選要移除什麼：

| 項目 | 預設 | 為什麼 |
|---|---|---|
| Gemini API 金鑰（環境變數） | ✅ 勾 | 等同帳號密碼，電腦轉手前務必移除 |
| 暫存的會議錄音（`%TEMP%` 裡整場會議的原始聲音） | ✅ 勾（有殘留時） | 只有程式被強制關掉時才會留下，電腦轉手前務必清掉（沒有殘留就不能勾） |
| 桌面捷徑 | ✅ 勾 | 這個工具專屬 |
| `google-genai` / `sounddevice` / `PyAudioWPatch` | ✅ 勾 | 只有這個工具在用（已經沒裝的不能勾） |
| 口譯功能的聲音輸出紀錄（`%LOCALAPPDATA%\TIO-Meeting-Genie`） | ✅ 勾 | 只有功能 6 會留下；有還沒改回的紀錄時，先把聲音輸出改回原本那顆再刪 |
| `numpy` / `scipy` | ⬜ 不勾 | 通用套件，別的程式很可能也在用（已經沒裝的不能勾） |
| ffmpeg | ⬜ 不勾 | 通用工具，剪片軟體等也常用 |
| Python 本身 | ⬜ 不勾 | 風險最高，移除可能讓別的軟體壞掉 |
| 程式資料夾 | ⬜ 不勾 | 勾了會在視窗關閉後刪除 |

勾有風險的項目時會再跳一次確認；按「開始移除」之前會把**實際要執行的指令**整份列出來。

🔴 **你產出的逐字稿、字幕、雙語對照檔一律保留**——解除安裝程式裡沒有任何一行程式碼
會去掃描或刪除它們。

**手動安裝**（開發/除錯用）：
```bash
pip install -r requirements.txt
```
另需 `ffmpeg` 在 PATH 上。API 金鑰放環境變數 `GEMINI_API_KEY`。

**只支援 Windows**——「錄電腦播放的聲音」用的是 Windows 專屬的 WASAPI，Mac/Linux 用不了。

要把這個工具組分享給別人？看 [`1_安裝說明（先讀這個）.md`](1_安裝說明（先讀這個）.md)。

## 六支工具

### 1. 會議即時字幕
會議進行中，字幕即時跑出來，結束自動存 `.md`（給人讀）和 `.txt`（即時備份）。

```bash
python scripts/live_caption.py --source system --vocab 深耕計畫 研發處
```
- `--source system`：錄**電腦播出來的聲音**（Teams / Meet / Zoom）← 線上會議用這個
- `--source mic`：錄麥克風 ← 實體會議室用這個
- `--source both`：兩者混合

灰字＝暫定字幕（約 1 秒出現，會一直修正），白字＝定稿。
定稿由 `SentenceGate`（`scripts/_live.py`）自己從 interim 按標點切句，**一句一鎖**；
模型換成新段落時，會先把舊段落還沒定稿的字送出（2026-09-19 修正：原本這一段一句都還沒切出來就換段時，
整段會消失）；
刻意不使用伺服器的 `input_transcription`——那個要偵測到講者停頓才會來，
連續演講會拖到一分鐘以上才吐一整包（實測 7 分鐘只出 1 段）。
**即時模式分不出講者**（實測 Live API 的 diarization 無效），要分講者請用工具 2。

產出兩個檔：
- `.md` — 正常按 Ctrl+C 結束時產生，給人讀的
- `.txt` — **每收到一段定稿就立刻寫入**。萬一程式當掉、電腦當機、或被強制關閉，
  整場會議的字幕還在這個檔裡（已實測：強制砍掉程式，`.md` 沒產生但 `.txt` 完好）。

> `.srt`（字幕軌）預設**不產生**——單獨點開只會跳出空的播放器，一般用不到。
> 真的要拿去掛在影片上時，加 `--srt` 參數即可。

### 2. 錄音／錄影檔 → 繁體逐字稿（含講者、時間軸）

```bash
python scripts/transcribe_meeting.py 會議錄音.m4a \
    --vocab 深耕計畫 研發處 會計室 教學組長 \
    --names 處長 秘書
```
產出 `會議錄音_逐字稿.md`（＋同名 `.json`）：

```
**[00:00:00] 處長**
好，那我們今天的研發處會議就開始了。第一個案子是深耕計畫的期中報告。

**[00:00:09] 秘書**
我這邊補充一下，就是那個經費核銷的期限已經延到10月31號了。
```
（整理正文時漏掉、再從原音單獨補轉回來的句子，標題後面會多一個「〔補轉〕」，說明見 5_使用說明。）

`--vocab` 很有用：實測它把「會計師」修回「會計室」、「計劃」修回「計畫」。
把單位名、計畫名、人名先餵進去，正確率差很多。

超過 **28 分鐘**的錄音會自動分段處理（`MAX_CHUNK_SEC = 28 * 60`）。
🔴 上限不是 token 算出來的 65 分鐘，而是官方 Limitations 寫的
「開啟 speaker diarization 或 word-level timestamps 時，音訊處理限 30 分鐘」——
超過的話**不報錯、照整份計費**；超過的部分會怎樣官方沒寫，
我們實測也沒有確認過任何一次「只轉出前 30 分鐘」的截斷。
另一條上限是官方明文的「單次請求最長 1 小時」（不開分講者時）——
早期文件寫的 65.4 分鐘是拿 token 上限反推的，**高估了**，實測 60.6 分鐘就會被擋。
文件與畫面訊息都要跟程式的實際門檻一致。
單段失敗不會拖累其他段落，輸出檔頭會列出缺了哪些時段。

### 3. 即時雙語字幕

```bash
python scripts/live_bilingual.py --source system --target zh-TW        # 快速模式：邊聽邊翻，延遲~1s
python scripts/live_bilingual_hq.py --source system --target zh-TW     # 準確模式：整句才翻，延遲~2-3s
```
聽演講/影片時，原文與譯文同時顯示（`--target` 用 zh-TW、ja 或 en，跟選單的三個選項一樣）。快速模式語序偶爾會卡住
（模型還沒聽完就先翻），準確模式等整句講完才送翻譯，語序正常但延遲較高。
`--source system`（電腦播出的聲音）／`mic`（麥克風）／**`both`（兩者混合，實體+線上會議用）**／
`file`（直接讀影音檔，不會錄到別的聲音）。

> `both` 是**逐取樣相加的真混音**。早期版本讓兩個來源共用一個佇列，結果是
> 「[麥克風100ms][系統100ms]…」交錯、而且音訊量加倍，辨識會亂掉。
> 🔴 2026-09-19 筆電實測又抓到一種：兩路**都持續送資料、但到達時間錯開**時（耳機靜音也一直送、Teams 通話也是），
> 舊寫法仍會交錯（80 秒送成 117.8 秒、講話那一路每 3 塊夾 1 塊空白）。現在混音在 `_live.mix_lanes`（三支共用），
> 要等正在送的每一路都湊滿一塊才相加。

### 4. 逐字稿轉雙語對照

```bash
python scripts/translate_transcript.py 會議.mp3 --to en \
    --glossary 深耕計畫="Higher Education Sprout Project"
```
吃錄音/影片檔、`.json` 逐字稿、或 `.srt` 字幕，整份丟給文字模型翻譯（看得到上下文，
品質比即時翻譯好很多）。輸出四種檔：對照 md、對照表（可貼 Word/Excel）、純譯文版、對照 json。
`--glossary` 鎖專有名詞的固定譯法；要雙語 srt 字幕軌的話加 `--srt`。

### 5. 逐字稿重新排版（純本機，不花錢）

```bash
python scripts/json_to_md.py 會議錄音_逐字稿.json --names 處長 秘書
python scripts/json_to_md.py 會議錄音_逐字稿.partial.json      # 救回中斷的轉檔（多半只有多段錄音留得下）
```
工具 2 每次都會在 `.md` 旁邊留一份同名 `.json`（原始段落資料）。這支把它重排成 `.md`，
**不呼叫 API、不花錢**。兩個場景：**超過 28 分鐘**被自動切成多段的錄音轉到一半當掉時，已經整段
轉完的部分留在 `*.partial.json`，用這支救回來（**28 分鐘以內是一整段處理**，要等那一段的
兩趟辨識、對齊、補轉全部做完才會存檔，**辨識中途**當掉就不會留下 `*.partial.json`、只能整份重轉；但那一段全部跑完之後才出事的話仍會留下，所以還是先看一眼桌面有沒有這個檔）；
講者名字填錯或想重排時，不必重轉整份錄音。多段錄音的講者編號是每段各自判斷的，
輸出檔頭會標明這點。

### 6. 即時語音翻譯（口譯模式）

```bash
python scripts/live_bilingual.py --source mic --target zh-TW --speak
python scripts/live_bilingual.py --source system --speak --speak-device "耳機"
python scripts/live_bilingual.py --list-devices          # 先看有哪些播放裝置
```
跟工具 3 的**快速模式是同一條連線**：`gemini-3.5-live-translate-preview` 的
`response_modalities` 本來就是 `["AUDIO"]`，翻譯語音一直都在回傳，舊版讀完文字就丟掉。
`--speak` 只是把它接到喇叭／耳機上，**不會多花一毛錢**（語音在伺服器端生成時就計費了）。

🔴 **回授迴圈**：`--source system`／`both` 是側錄**系統預設播放裝置**正在播的東西。
翻譯如果也送到同一顆，會立刻被錄回去、再翻一次、再播一次，越滾越亂而且一直燒錢。
所以這兩個來源**強制**要用 `--speak-device` 指定另一顆裝置（通常是耳機），
選到預設那顆會直接擋下來（離開碼 2）。
「Microsoft 音效對應表」「主要音效驅動程式」這種**跟著預設走的轉接器也會被擋**
——只比名字的話，它們看起來像別顆裝置，其實聲音還是送到預設那顆。

`--source mic` 只會警告不會擋：麥克風收不收得到喇叭的聲音，程式無法判斷，請自己戴耳機。
收到的話，模型會一直重複翻自己的聲音、停不下來，這段時間也一直在計費（2026-09-28 實際遇到、用真 Google 模擬重現）。
`--source file` 沒有這個問題。

其他行為：播放佇列上限 6 秒，塞爆時**丟最舊的**（寧可少半句，也不要讓耳朵越落後越多），
結束時會回報**送進播放裝置**幾秒（不是「聽到了幾秒」——寫得進裝置不代表有聲音，
見 `references/gemini-speech-guide.md` 的 6.2）、跳過幾秒。
播放裝置開不起來時只警告，字幕照跑。

## 成本

實測音訊 = **25 token/秒**，一小時會議約 90,000 tokens。

官方單價取自 ai.google.dev/gemini-api/docs/pricing（2026-09-18 查）。NT$ 以 1 USD = 32 TWD 換算。
工具 4 與工具 2 的對齊是 2026-09-19 實測；`gemini-3.5-transcribe`／`transcribe-live` 的 API 不回報輸出 token，表中那部分是官方估算。

| 工具 | 模型 | 輸入 | 輸出 | 1 小時 |
|---|---|---|---|---|
| 1 即時字幕 | `gemini-3.5-transcribe-live` | $3.50/1M（$0.005/分） | $21.00/1M（$0.004/分・文字） | US$0.54（NT$17） |
| 2 逐字稿（**兩趟**） | `gemini-3.5-transcribe`＋`3.5-flash`（對齊） | $2.00/1M（$0.003/分）＋$1.50/1M | $12.00/1M（$0.002/分・文字）＋$9.00/1M | ~US$0.62（NT$20） |
| 3 雙語字幕・**準確** | `transcribe-live`＋`3.5-flash-lite` | ＋$0.30/1M | ＋$2.50/1M | ~US$0.57（NT$18） |
| 3 雙語字幕・**快速** | `gemini-3.5-live-translate-preview` | $3.50/1M（$0.0053/分） | **$21.00/1M（$0.0315/分・音訊）** | **US$2.21（NT$71）** |
| 4 逐字稿轉雙語 | `gemini-3.5-flash` | $1.50/1M | $9.00/1M（含思考） | ~US$0.51（NT$16） |
| 5 逐字稿重新排版 | 不呼叫模型 | — | — | **0** |
| 6 即時語音翻譯 | `gemini-3.5-live-translate-preview` | 同 3快 | 同 3快 | **US$2.21（NT$71）** |

🔴 **判斷貴不貴看「輸出是文字還是音訊」，不是看模型名字。** 工具 1 與工具 3快 的輸出單價都是
$21.00/1M，但前者輸出文字（$0.004/分）、後者輸出音訊（$0.0315/分）——差 8 倍。

> 🔴 **快速模式的成本是準確模式的 4 倍。** 判準是 `response_modalities`，不是模型名字：
> `gemini-3.5-live-translate-preview` 是 `["AUDIO"]`，**輸出是語音**，而語音輸出
> 每分鐘 $0.0315、文字只要 $0.004 —— 兩者的每百萬 token 單價同樣是 $21.00，只看單價看不出來。
> 準確模式走純文字轉錄＋翻譯，所以便宜。
>
> 量到的實際值：2026-09-19 用 10 分鐘音檔完整實測，輸入、輸出各 **25.0 token/秒**（14,975／599 秒），
> 每小時 US$2.20（約 NT$70.6），與官方 25 token/秒吻合（早期只量 20 秒得到 23.8，已被這次取代）。量法：把每一則 `usage_metadata` 加總起來。
> 🔴 `usage_metadata` 是**每則**的用量、不是累計值，只讀最後一筆會少算 20 倍。
>
> 反過來說：語音本來就會產生、也已經計費，所以**工具 6 把它播出來不用另外花錢**。

🔴 **免費層雖然不扣款，但 Google 條款明文說免費層的內容會被拿去改進產品、
且人工審閱者可能會讀到，並警告不要送機密資訊。**
涉及人事、經費、學生個資的會議，請先開通付費層再用。

**額度也已經查不到了**（2026-09-08 查證）：官方 rate-limits 頁面移除了逐模型的
額度表格，改成叫使用者登入 AI Studio 自己看，而且註明
"Specified rate limits are not guaranteed and actual capacity may vary."
所以**不要在任何文件裡寫免費層的 RPM/RPD 數字**——查不到、也不保證。

其他實測到的額度行為：
- RPD 在**美西午夜**重置（台灣下午 3～4 點）
- 額度算在**專案**上，不是金鑰上；同專案多把金鑰共用一份額度
- 預覽版模型（本工具的快速模式用 `gemini-3.5-live-translate-preview`）額度更嚴
